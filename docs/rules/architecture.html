アーキテクチャと arrangement.json スキーマ

中心思想 — データ駆動の設計。 編集作業はコード（scripts/*.py）ではなく arrangement.json の編集で完結する。 スクリプトは楽曲・人数に非依存な汎用エンジンとして保ち、楽曲固有の判断はすべて JSON 側に置く。

arrangement.json（単一の真実の源）

音源書き出し（build_mix.py）と動画書き出し（build_video.py）の両方がこのファイルを読む。

キー意味

vocalists

名前（内部キー）→ 設定のマップ。

フィールド意味

pan定位 -1.0=左 / 0=中央 / 1.0=右（等パワー）

フィールド意味

フィールド意味

dim_level歌っていない人の明度（0=黒〜255=白）。「透明度」を明度で表現

スクリプト

scripts/build_mix.py（音源エンジン）

  • BGM をステレオ float32 で土台にし、各セクションのボーカルを加算合成する。
  • モノラル音源はステレオに複製、apply_pan() で等パワー定位。
  • 各セクション境界に crossfade_sec のフェード窓（fade_window()）をかけて段差・ノイズを防ぐ。
  • セクション単位の gain_db を適用後に全トラック合成。ピークが 0.99 超なら全体を正規化して音割れを防止。

scripts/build_video.py（動画エンジン）

  • 黒背景に vocalists 全員の名前を横一列で常時表示する。
  • 各区間で歌っている人（active）だけを白(255)、他は明度 dim_level の灰で描き、「歌っている人をハイライト」する。
  • 歌唱区間の隙間（イントロ・間奏・アウトロ）は全員薄い。
  • active の組み合わせ（frozenset）ごとにフレーム画像を1枚キャッシュし、concat demuxer で動画化する。
